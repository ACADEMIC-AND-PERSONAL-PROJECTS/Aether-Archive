## 4. The probe falsified the documentation — before any test did

First probe run, with `VITE_API_BASE_URL=http://localhost:8099/api/v1` — the exact value `.env.example`
and `vite-env.d.ts` suggested:

```
 FAIL  src/api/probe-real-api.test.ts > … > should parse a real photo list
 ApiError: Not found (404)
```

The client had composed `…/api/v1/api/v1/photos`: it adds the `/api/v1` prefix itself, so the base
must be an **origin** with no suffix — and every unit test passed while the documented configuration
was broken, because no test exercised the composition `apiRequest` actually performs. Confirmed
directly, then corrected in `.env.example`, `vite-env.d.ts`, the `client.ts` doc and the tests, which
now pin the composition at the `apiRequest` level:

```
$ curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8099/api/v1/api/v1/photos   → 404
$ curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8099/api/v1/photos          → 200

# the same probe file, after the correction:
 Test Files  1 passed (1)
      Tests  5 passed (5)
```

## 6. Probe — what the test environment actually provides

The client's deadline, cancellation and parsing paths run inside Vitest + jsdom; a temporary probe
recorded the machinery they rely on there (deleted afterwards):

```
deadline {"statics":{"timeout":"function","any":"function"},"globals":{"fetch":"function","Response":"function","DOMException":"function"},"reasonCtor":"DOMException","reasonName":"TimeoutError","reasonIsInstanceOfTheGlobal":false}
cancel   {"cancelCtor":"DOMException","cancelName":"AbortError","cancelIsInstanceOfTheGlobal":false}
```

`AbortSignal.timeout`, `AbortSignal.any`, `fetch` and `Response` are all present in the jsdom run —
and the reason is a `DOMException` that is **not** an instance of the global one (Node's class, the
global being jsdom's): the measured justification for matching error **names**, exactly as
`classifyTransportFailure` documents. The same shapes outside jsdom, straight from Node 22:

```
timeout  : DOMException | TimeoutError
refused  : TypeError | fetch failed | ECONNREFUSED
dns      : TypeError | fetch failed | ENOTFOUND
cancel   : DOMException | AbortError
```

## Verdict

**GREEN.**

**Not covered / SKIPPED**

- **No CI run**: E6-S1 is Sprint 4; every check above is a local run.
- **The `empty-archive` answer of `/photos/random`** was not probed — the dev database holds photos,
  so only the resolving contact was measured. The code path is pinned by unit tests with the real
  code (measured in §3 at the 400); a seed-free probe is E1-S10's smoke collection territory.
- **The 5xx and non-JSON-200 branches** are pinned with stubbed responses: the archive has no endpoint
  that fails those ways on demand, and inventing one is not this story's scope.
- **No view fetches data yet** — splash/river/workshop are placeholders; `queryKeys.ts` and the cache
  are the wiring E3/E4/E5 land on.
- **AC wording vs the contract**: the story says "types mirroring `_docs/openapi.yml` (`ArchiveItem`,
  …)", but the contract (163 lines, grepped) publishes `Photo`, `Dump` and `DumpCreate` — **no**
  `ArchiveItem` and no error schema. `src/types/api.ts` mirrors what the contract publishes, keeps the
  `ProblemDetail` shape from ADR-013 (the probe in §3 shows it is the real one), and names the omission
  in the file. Interpreted, not skipped; the PR carries the same note.
- **`npm run preview` runs without the dev proxy** — a preview against a real API is the container's
  job; ADR-016 records it.
