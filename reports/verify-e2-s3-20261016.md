## 3. Palette wipe + emission contract

```
bg-red-500     : 0      text-3xl      : 0
bg-transparent : 1      text-current  : 1
```

- the raw palette and the default type scale cannot compile;
- the static utilities a glass UI needs (`bg-transparent`, `text-current`) survive the wipe;
- **emission contract**: a probe rule using `var(--text-xs)`, `var(--aura-glass)` and `var(--aura-accent)`
  from raw CSS made all three tokens emit (1 each) — Tailwind emits `@theme` variables lazily and a `var()`
  reference anywhere in compiled CSS counts as a use, so raw consumers (the future `glass.css`) are safe.

## 9. References consulted (design-system skill, Part 0)

- **Tailwind — *Detecting classes in source files*** (https://tailwindcss.com/docs/detecting-classes-in-source-files):
  automatic detection is an optimisation of a heuristic; `@source` / `source(none)` make the candidate set
  explicit. → *A build’s inputs are a declaration, not a discovery.*
- **MDN — *env()*** (https://developer.mozilla.org/en-US/docs/Web/CSS/env): `env()` takes a fallback second
  argument, and insets only exist where the viewport declares `cover`. → *Device geometry is data with a
  zero default.*
- **MDN — *overscroll-behavior*** (https://developer.mozilla.org/en-US/docs/Web/CSS/overscroll-behavior):
  containment stops scroll chaining and pull-to-refresh, and the root’s colour is what shows past the
  edges. → *Own the edges; the last pixel is the app’s.*
