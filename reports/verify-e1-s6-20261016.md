## 4. A real defect the end-to-end test found

PostgreSQL keeps **microseconds**, so the 201 said `…578181872Z` while the feed said `…578182Z` for the same
photo — two different values for one photo, which a frontend keying on `uploadedAt` would have seen as two
photos. Uploads are now stamped `truncatedTo(ChronoUnit.MICROS)`, and the flow test asserts the 201 and the
feed name the same instant. This is the kind of thing only an end-to-end test through the real database
finds; the slice test could not have.

## 5. Failure paths

| Case | Answer |
| --- | --- |
| no `file` part | 400 `missing-request-part` |
| `category` absent / blank / unknown | 400 `validation-failure`, `errors` naming `category` |
| file bytes are not an image | 415 `unsupported-image-type` |
| upload over `AETHER_MAX_UPLOAD_MB` | 413 `upload-too-large` (service ceiling; the container ceiling is covered by `MultipartUploadCeilingTest`) |
| `category` posted as a **file part** | 400 `invalid-parameter` — it was a **500** before this story (`MethodArgumentConversionNotSupportedException` is not an `ErrorResponse`), probed through real Tomcat |
| empty archive, `/random` | 404 `empty-archive`, distinct from `not-found` on purpose |
| the row cannot be saved after the file is written | the stored file is deleted (compensation), `images/` left as it was |
