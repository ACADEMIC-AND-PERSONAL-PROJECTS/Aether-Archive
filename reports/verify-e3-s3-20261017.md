## Scenarios (`transition-probe2.mjs`, 390 × 844 emulated)

Viewport check on a loaded page (`node /tmp/aether-e3s3-probe/viewport-probe.mjs`): `innerWidth 390`,
`innerHeight 844`, `documentElementClientW 390`, `main 390 × 844`, meta viewport
`width=device-width, initial-scale=1, viewport-fit=cover`. The probe's own top-level `viewport` field is
`980 × 2121` because it is sampled on `about:blank`, which has no meta viewport — the per-scenario rects
(`veilRect w 390`, `clientH 844`) and this check are the real ones.

**coldNavigation — 74 frames over 1209 ms, into a lazy chunk.** Rows are the frame where a value changed:

```
ms 0   /            opacity 1      transform none            anims 0  scrollH 844  h1 Aether Archive
ms 9   /river       opacity 1      transform none            anims 0  scrollH 844  h1 Aether Archive
ms 56  /river       opacity 0      matrix(…, 16)             anims 1  scrollH 860  h1 The River
ms 126 /river       opacity 0.438  matrix(…, 8.99)           anims 1  scrollH 853
ms 193 /river       opacity 0.718  matrix(…, 4.52)           anims 1  scrollH 849
ms 276 /river       opacity 0.890  matrix(…, 1.75)           anims 1  scrollH 846
ms 659 /river       opacity 1      matrix(…, 5.98e-12)       anims 1  scrollH 844
ms 676 /river       opacity 1      transform none            anims 0  scrollH 844
```

`mains: 1`, `status: 0`, `scrollers: 0` and `scrollbar: none` in **every** frame of the run. The URL
changes at ms 9 while the outgoing view is still painted — the new view mounts at ms 56, so the entry is
on the real view and the Suspense fallback never appears.

**scrolledPage — leaving `/check` at `scrollY 400`.** `scrollY 400 → 16 (ms 18) → 1 (ms 251) → 0 (ms 351)`
as `scrollHeight` falls `1780 → 860 → 844`. No scroll API is called: the browser clamps as the shorter view
replaces the taller one. Scroll restoration between two scrollable views is not implemented and is not
claimed — it is E5-S1's.

**back (67 frames) / forward (134 frames)** over real `history.back()` / `history.forward()`: both replay
the entry from opacity 0 / 16 px to settled, with the correct `h1` at every frame and `mains: 1` throughout.

**interrupted at 90 ms.** The first entry reached `opacity 0.5229, transform matrix(1,0,0,1,0,7.63)` at
ms 81 and was replaced at ms 99 by `/curate` starting again from `opacity 0, matrix(1,0,0,1,0,16)`, which
settled at ms 698. One `<main>` at all times, no stuck state. This is a *restart*, not a resume from the
current value — that is what "interruptible" means here, and ADR-022 records it as such.

**reduced motion, both readings** (`Emulation.setEmulatedMedia`), same navigation:

```
no-preference  matchMedia false  distinct opacities 37  maxScrollH 860  offsets: 16 → 8.4e-12
reduce         matchMedia true   distinct opacities 37  maxScrollH 844  offsets: 'none' | matrix(1,0,0,1,0,0)
menu veil      aether-fade / 0.32s under BOTH readings
```

Under `reduce` the entry still fades — criterion 4 asks for opacity-only, not for nothing — and no frame
carries a vertical offset: the menu sheet's `top` is a single value (642, measured over 43 frames) while
under `no-preference` it runs 666 → 642.

**A `position: fixed` overlay opened mid-flight.** `wrapperTransform matrix(1,0,0,1,0,2.59)` →
`veilRect {x 0, y 3, w 390, h 844, bottom 847}` in an 844 px viewport; after the entry,
`wrapperTransform none` → `veilRect {y 0, bottom 844}`. The menu is a descendant of the wrapper
(`wrapper.contains(sheet) === true`), so while a transform is live it is the containing block. Bounded by
the entry's length and by the drift distance; a portal would remove the coupling (ADR-022 §5).

**Settled state.** `{transform: "none", animationName: "aether-enter", animationFillMode: "none",
running: 0}` — no fill mode, nothing running, and no containing block afterwards.

## What jsdom cannot say, and what is claimed instead

`node /tmp/aether-e3s3-probe/jsdom-probe.mjs` against jsdom 30.1.3:

```
{"matchMedia": "undefined", "document_startViewTransition": "undefined", "getAnimations": "undefined",
 "element_getAnimations": "undefined", "animationEvent_ctor": "undefined", "requestAnimationFrame": "function",
 "scrollingElement": null, "CSS_supports_startingStyle": false}
```

So a JS-driven motion layer would have put the reduced-motion switch and the animation itself outside the
unit suite entirely. The suite pins the *vocabulary* instead — which class a component carries, that every
`var(--motion-*)` and every `animate-[…]` keyframe name resolves in `global.css`, that `aether-enter`
carries `translateY(var(--motion-distance-enter))` and ends at `transform: none`, and that `aether-fade`
contains no transform at all — and the claims about what a user sees come from the Chromium runs above.

## The mutants — four changes, and one of them survived the first time

Each mutant was applied to the production file, run against the tests that should notice, and reverted
(checked afterwards: `git diff --numstat` for `global.css` is back to its measured `55 23`).

| Mutant | Expected to fail | Result |
| --- | --- | --- |
| `--motion-distance-enter: 16px` → `8px` | `tokens.test.ts` | **killed** — `expected '8px' to be '16px'`, 1 failed / 7 passed |
| `@keyframes aether-enter` → `aether-enter-renamed` | `tokens.test.ts` | **survived** on the first run (8 passed) — see below |
| `viewIdentity` → `return pathname` | `route.test.ts`, `RouteTransition.test.tsx` | **killed** — 3 failed / 7 passed: `expected '/river/' to be '/river'`, `expected '//' to be '/'`, and the remount test |
| the `:root { --motion-distance-enter: 0px }` binding removed from the `reduce` block | `tokens.test.ts` | **killed** — `Error: Missing --motion-distance-enter in the block` |

**The surviving mutant was a real hole, and it is fixed.** The guard asserted
`SOURCE.toContain("@keyframes " + name)` — and `@keyframes aether-enter-renamed` *contains*
`@keyframes aether-enter`, so a keyframe renamed to a longer one passed, as did `bracedBlock`'s
`indexOf` lookup, which then happily asserted about the wrong block. It is the same class of mistake as
E1-S10's first path guard: comparing what a string *spells* rather than what it *names*. Both lookups now
match on the trailing brace (`@keyframes\\s+<name>\\s*\\{`, via `keyframeBlock`), and the same mutant now
fails two tests with `aether-enter is referenced but has no @keyframes`. Without the mutant the hole would
have shipped green: the test's name promised a guarantee it did not make.

## View Transitions

`node /tmp/aether-e3s3-probe/vt-probe.mjs`, HeadlessChrome/152.0.0.0: `typeof document.startViewTransition`
is `"function"`, and a transition runs **5** UA pseudo-element animations at **250 ms** each —
`-ua-view-transition-group-anim-root`, `-ua-view-transition-fade-in`, `-ua-view-transition-fade-out` — under
`prefers-reduced-motion: no-preference` **and** under `reduce`, identically. The API does not handle
criterion 4 for you, and its default duration is not one of §5's. React Router 8.4.0 does drive it
(`node_modules/react-router/dist/development/lib/components.js`: `typeof
router.window.document.startViewTransition === "function"`, plus a `warnOnce` and no transition when it is
missing), so it stays available as a later layer on the same tokens — ADR-022 §6.

## Not covered — residual risk

- **No physical device.** Every browser number is headless Chromium 152 at an emulated 390 × 844. Touch,
  iOS Safari's dynamic viewport behaviour and the `100dvh` reflow that follows a browser-chrome collapse
  are unverified; the E3-S2 report already names the same limit.
- **No Firefox/WebKit run.** `backdrop-filter` degradation is covered by CSS only, and the frame numbers
  above describe Chromium's compositor.
- **`prefers-reduced-motion` is emulated**, not a user setting, and the emulation covers only the media
  query — a user with OS-level "reduce transparency" is not modelled anywhere.
- **The 16 px overflow is real for the length of the run** (`scrollHeight` 860 in an 844 px viewport). No
  scrollbar is painted in any frame measured, and the overflow is gone when the entry ends, but a
  scroll-locked page during an entry is not something this report can rule out for *every* engine.
- **Scroll restoration is absent by design** (see scrolledPage) and is E5-S1's to own.
- The strip's frames were captured from the built bundle with a stub backend, so the River view shows its
  placeholder sentence rather than a feed — that is today's truth (E5-S1).
