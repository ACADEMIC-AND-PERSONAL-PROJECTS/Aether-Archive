## 5. Security fix — symlinked staging directory (review round 1)

The first review found, by execution, that a symlinked `<dataDir>/tmp` was followed when the staging area was
emptied on boot, deleting the link target's contents. Full write-up:
`reports/security-finding-e1s2-symlinked-staging.md`. Re-verified here with the packaged jar:

```
$ mkdir -p $D/data $D/elsewhere && echo keep-me > $D/elsewhere/keep.txt && ln -s $D/elsewhere $D/data/tmp
$ AETHER_DATA_DIR=$D/data java -jar …jar
exit_code=1
ERROR … Aether Archive cannot start: the staging directory '/tmp/tmp.…/data/tmp' is a symbolic link and its contents are deleted on every boot. The data directory must contain real directories: point AETHER_DATA_DIR at the target location instead (the data directory itself may be a symlink).
Started lines: 0                      # the port is never bound
$ ls -l $D/elsewhere ; cat $D/elsewhere/keep.txt
keep.txt  8B                          # the link target is untouched
keep-me
```

**PASS** — the boot refuses, nothing is deleted, and a symlinked *data directory* (a legitimate layout) still
works. The accompanying test fails when the guard is removed (verified by mutation during the fix), so it
genuinely pins the behaviour rather than merely passing.

## 6. CORS behaviour

`WebMvcConfigCorsTest` (MockMvc, test-only controller): an allowed origin receives
`Access-Control-Allow-Origin`; a disallowed one is refused with `403 Invalid CORS request` and no header —
Spring 6's real behaviour for a disallowed simple request, which is stricter than "no header, 200". The
wildcard pattern form (`http://192.168.*.*:5173`) is covered, and an empty list registers no mapping at all.

**PASS** — CORS is restricted to the configured origins, and the documented wildcard form works.
