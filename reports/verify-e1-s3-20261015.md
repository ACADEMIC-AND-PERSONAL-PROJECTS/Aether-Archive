## 4. The `.env` bridge works

Spring Boot does not read dotenv files, which the E1-S11 review caught being documented as if it did.
The bridge was proven with a throwaway probe (no `.env` exists in the repository): a config declaring
`optional:file:../.env[.properties]`, started from a subdirectory, read a dotenv-style file one level up
(`db=probe-db user=probe-user`). A second probe confirmed the documented precedence — later imports win, and
imported values outrank the importing document.

**PASS** — and because both entries are `optional:`, machines and CI without a `.env` are unaffected.

## 5. Schema pinning beyond `validate`

`validate` compares column *types* only — it happily accepts a `varchar(255)` column for a `varchar(80)`
mapping. `SchemaBaselineTest` therefore pins the type, length and nullability of all eleven columns against
`information_schema`, and the repository slices cover the constraints the service layer will rely on:

- the unique position per item (`uk_photo_archive_item_display_order`), with unassigned photos
  (`display_order IS NULL`) correctly outside it;
- the `#RRGGBB` check on `background_color` and the `0..5` range on `display_order`;
- nullable `archiveItem`, `displayOrder` and `title` really accepting null;
- the river order, **including equal timestamps** — the `id` tiebreaker is exercised, and repeated reads
  return an identical sequence.
