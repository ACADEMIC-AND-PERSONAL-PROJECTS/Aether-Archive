## What jsdom still cannot say, and what is claimed instead

- **`touch-action` has no effect in jsdom**, so the test asserts only that the surface still declares
  `touch-pan-x touch-pinch-zoom` (`toHaveClass`). That test fails if the class is dropped; it cannot fail
  if a *browser* ignores it. The effect is the Chromium trace above, including the failing half
  (`forced auto` → `pointercancel`, no re-roll), so the claim is not carried by a green check alone.
- **Hit testing does not exist in jsdom**: a button under the image would pass every unit test. The
  `elementFromPoint` reading above is the evidence.
- **`click` after a drag**: Chromium fired no `click` after the synthesised drag, so the browser does not
  currently exercise the suppression path for a long drag — the unit tests do, and the mutant above shows
  they would die without it. The suppression is for drags a browser *would* treat as a tap.

## Not covered — residual risk

- **A real device.** Chromium was driven synthetically over CDP; no physical finger, no iOS Safari. Whether
  a real touch tap leaves the focus ring the synthetic one left is **not measurable here** and is the one
  new question this slice raises. `100dvh` and safe-area insets remain unverifiable headless.
- **Gesture recognition beyond Chromium.** The `pointercancel` trace is Chromium's; Firefox and Safari are
  assumed to behave the same way for `touch-action` (the property is standard), not measured.
- **The backend suite.** Not run: no backend file is touched. The random-photo response used by the probe is
  the archive's own JSON shape (`Photo`), served by a stub — the real backend path for this story was
  measured in slice A (`reports/verify-e3-s1a-20261016.md`).
- **E3-S2's own criteria** (overlay, focus trap, backdrop tap, focus return) are untouched: this slice
  lands the open *intent* and both ways to close it, and the view's doc comment says so.
- **The dev data directory.** The probe served the same generated 1200×1800 PNG the throwaway archive
  holds; the real dev configuration still resolves to a non-existent placeholder (slice A's environment
  finding, unchanged).
