## 2. Payload — every reading measured, one adopted

§4.2's snippet was written before the packages were installed. DESIGN-SYSTEM §4.4 governs the
choice: **latin subsets only** and an added payload **< 200 KB**. All four readings were measured
on the real packages (`node_modules`) and the final `dist/`:

| Reading | Composition | Bytes | Verdict |
| --- | --- | ---: | --- |
| **A — §4.2 literal** | Playfair `400.css` + `500.css` + Inter `wght.css`, every subset they reference (8 + 8 + 7 files) | 114,812 + 120,060 + 218,512 = **453,384 B** (453.4 kB) | ✗ 2.3× the budget |
| **B — latin Playfair, all-subsets Inter** | `latin-400` + `latin-500` + Inter `wght.css` | 99,904 + 218,512 = **318,416 B** (318.4 kB) | ✗ |

Why Inter is hand-declared: `@fontsource-variable/inter` ships **no per-subset entrypoint** —
its seven CSS files (`index`, `opsz`, `opsz-italic`, `standard`, `standard-italic`, `wght`,
`wght-italic`) all reference every subset; `wght.css` alone resolves to 218,512 B of woff2. The
packaged **latin** woff2 is therefore declared once in `global.css` (block 2), one file for the
whole axis — it answered both 300 and 700 in the probe. The static alternative (reading C) costs
109,916 B for two weights and 164,844 B for three, in one file per weight.

Costs to the rest of the bundle: the stylesheet grew **480 B** (8,697 → 9,177 B) with the faces
and the two utilities; the entry chunk is unchanged (same hash). `@fontsource/inter` was installed
only to measure reading C and removed — `node_modules/@fontsource/` now contains only
`playfair-display`.

## 3. What changed

- `frontend/src/main.tsx` — the two Playfair latin imports, before `./styles/global.css`.
- `frontend/src/styles/global.css` — the new "2. Faces" block (comment + the Inter `@font-face`),
  `--font-*: initial` in the reset, `@theme static` with the two families, and the base rule
  `body { font-family: var(--font-ui); letter-spacing: var(--tracking-ui); }`. Sections renumbered.
- `frontend/src/features/{splash,river,workshop}/*.tsx` — `font-display` on the three `h1`s.
- `frontend/package.json` + lockfile — the two Fontsource packages.

Two wiring decisions worth the reviewer's eye:

1. **`@theme static`, not `inline`.** The values are static (nothing rewrites them at runtime,
   unlike the palette), so they belong in the theme layer where `font-display` / `font-ui`
   compile from the same declaration; `static` forces emission to `:root` because only raw CSS
   (`body`) reads `--font-ui` — `inline` would also make the alias self-referencing. Evidence:
   dist CSS contains the two variables in `:root` and the compiled utility; the probe resolves
   both through computed styles.
2. **`--font-*: initial`** joins `--color-*: initial` in the reset, so `font-sans` and friends
   cannot compile (ADR-017's one-definition-per-scale rule).

## 4. Browser probe (offline Chromium, built app)

Method: the built app served by a local Python server (`/tmp/opencode/serve_probe2.py`), a probe
page assembled from `dist/index.html` (head script + one module), and
`chromium-browser --headless=new --dump-dom`. `--dump-dom` snapshots at the document `load` event,
so a **25-second image on a second local port** shifts that snapshot far past the probe's JSON write.
No request leaves localhost.

Two findings, now recorded in ADR-019 for reuse:

1. **Probe from a routable URL.** Served as `/probe-fonts5.html`, React Router matched nothing and
   rendered `null`: `#root` stayed empty for 25 s and no chunk was fetched — silently, no error.
   An execution marker appended to the bundle (temporary, removed by the rebuild) proved every
   module had run; only the route was wrong. The probe rewrites the URL with
   `history.replaceState(null, "", "/")` before the entry module runs.
2. **`--dump-dom` never paints.** Font faces stay `unloaded` and no woff2 is requested on its own,
   and `document.fonts.ready` resolves at the `load` event (25 s). The probe triggers every
   declared face explicitly with `document.fonts.load(...)` — which is exactly the evidence the
   story needs (CSS face → packaged file → usable face), independent of paint.

## 6. Notes

- **No unit test asserts typography, deliberately.** jsdom has no font matching or layout, so a
  passing test there would prove nothing about the shipped fonts. The evidence is the build
  listing, the dist CSS inspection, and the real Chromium loads above.
- The `woff` legacy twins (55,000 B) ship inside the packaged Playfair entrypoints. Dropping them
  would mean hand-writing those `@font-face`s to save 55.0 kB; the budget does not require it
  (ADR-019).
- The Inter `@font-face` points at a packaged hashed path — a future package update that renames
  files fails the build, never the runtime.
- DESIGN-SYSTEM §4.2/§4.3 were updated from the pre-measurement snippet to the shipped reality;
  §4.4's budget line now carries the shipped figure (74% of budget). Probe pages/scripts lived
  only in `dist/` (gitignored) and are gone after the final rebuild.
