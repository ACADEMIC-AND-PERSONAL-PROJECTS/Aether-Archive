## OWASP-oriented review

**File Upload Cheat Sheet** (https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) — verified point by point:

- **Client-side validation is convenience, not a boundary.** `frontend/src/lib/upload/validation.ts:12-14` says so explicitly; the server re-validates. The client checks only empty/declared type/size (`:111-134`), consults **no filename** (`:16-20`), and deliberately does not re-implement magic-byte sniffing (`:21-25`).
- **Content type is not trusted; magic bytes are checked.** `StorageService.store` reads a 64-byte header, maps the declared media type, detects the format from the bytes, and requires declared == detected (`StorageService.java:104-121`). A text file declared `image/png` gets 415.
- **Extension whitelist.** `ImageFormat` accepts JPEG/PNG/GIF/WEBP/AVIF and writes the detected format's extension (`StorageService.java:169-172`); the client's `ACCEPT_ATTRIBUTE` mirrors the five browser-known types (`validation.ts:46`).
- **Server-generated filename.** `UUID.randomUUID()` + validated extension; the client's original filename is ignored (`StorageService.java:97`, `:169-171`). `grep` for `getOriginalFilename|originalFilename` over `backend/src` → **zero hits**, so neither the controller nor the service ever uses it.
- **Size limit enforced twice.** `MultipartConfig` sets the container's file ceiling to `max-upload-mb` and the request ceiling to file + 1 MiB, staging on disk (`MultipartConfig.java:45-51`); `StorageService.copyWithLimit` counts the actual bytes and throws at the first byte over the limit (`StorageService.java:205-228`), so neither a header nor `MultipartFile.getSize()` can enlarge it. The client accepts exactly the limit and refuses the first byte over (`validation.ts:107-125`), matching the server.
- **Storage containment.** Writes go to `tmp/` then `ATOMIC_MOVE` into `images/`; both directories and the destination are resolved with `toRealPath` and checked with `requireInside` (`StorageService.java:161-194`, `:300-327`). The leaf-link case is accepted at the write site by design (the move replaces the link), as recorded in `.claude/rules/security.md`.
- **Serving.** `/images/**` is a handler over `file:<data>/images/`, no second location, no directory listing, media type from the stored extension, and `X-Content-Type-Options: nosniff` on every answer including 404s (`ImageServingConfig.java:88-102`, `:120-136`). The known symlink residual is #79/E6-S17 and is not request-reachable.
- **Client downscale does not create a server bypass.** Only JPEG/JPG/PNG are re-encoded; WebP/GIF/AVIF are left untouched; the returned `File` carries the **encoded blob's** type, not the requested one, so a browser that falls back to PNG is sent as PNG (`downscale.ts:276-350`). The server still sniffs. A failure returns the original file; the upload is never blocked by the optimisation (`downscale.ts:343-346`).
- **Gaps recorded, not hidden**: no antivirus/sandbox (local, single-user, user-picked files); uploads are not re-encoded server-side and EXIF is preserved (the archive is the product, local-only); symlink serving is #79.

**XSS Prevention Cheat Sheet** (https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html):

- A sweep of `frontend/src` for `dangerouslySetInnerHTML|innerHTML|eval\(|new Function|document\.write|srcDoc` → **zero hits**. No escape hatch is used anywhere.
- File names are rendered as React text and as an `aria-label` attribute: `SelectionGrid.tsx:81-84` (`Remove <file name>`), `:136-138` (text span), `:100-110` (blob URL in `src`, not user text). React escapes both contexts; the file name never becomes a tag, attribute name, URL or CSS.
- The splash renders the server's `src` as a **blob URL produced by decoding the bytes** (`hero.ts:123-136`), not as a server string in an `<img>`; the `<img>` is only mounted after `decode()` resolves. Upload failures render fixed sentences mapped from the problem `code` (`WorkshopView.tsx:95-108`), never the server's `detail`/stack.
- No user data reaches `dangerouslySetInnerHTML`, `innerHTML`, `outerHTML`, `document.write`, `eval`, `new Function`, script/style/href contexts, or event-handler strings. The only URL values are `photo.url` (N1) and the relative API path; both are fetched with `fetch`, not injected as markup.
- No CSP yet (N3) — hardening for the deployment story, not a substitute for the above.

**REST Security Cheat Sheet** (https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html):

- **CORS**: only the configured origin patterns are allowed; `allowCredentials(false)`; an empty list disables CORS entirely (`WebMvcConfig.java:29-39`). Dev's `192.168.*.*:5173` pattern and the localhost default are dev-only configuration, not a production wildcard.
- **CSRF**: not implemented; `POST /api/v1/photos` is a state-changing request and a cross-site `multipart/form-data` form/fetch can reach it. This is **#71/E6-S13** (`p1`), carried, not a new Sprint 3 behaviour. CORS does not mitigate it.
- **Input validation**: `category` is a required field at the contract level, constrained by `@NotBlank` + `@Pattern(ValidationConstraints.CATEGORY_PATTERN)`; a missing/blank/wrong value is a field-level 400 (`PhotoController.java:63-75`). Multipart malformed/missing-part/oversize cases are mapped to 400/413 (`ApiExceptionHandler.java:142-153`, `:294-311`).
- **HTTP methods/status**: only GET/POST are declared; 201 on create, 400/404/409/413/415 as appropriate; no catch-all 200.
- **Error responses**: RFC 9457 `ProblemDetail`; storage failures return a path-free sentence and log the cause rather than serialising it (`ApiExceptionHandler.java:160-165`); argument conversion and unreadable-body handlers do not echo rejected values or class names (`:203-228`, `:286-311`); unknown resources get a generic 404 (`:318-322`). No stack traces or filesystem paths in responses.
- **Versioning**: `/api/v1` throughout (`PhotoController.java:45`).
- **Authentication/rate limiting**: absent by design for a local single-user archive; LAN reachability is ADR-008's accepted risk, and #71 covers the browser cross-site vector.

**Secrets Management Cheat Sheet** (https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html):

- `.env` and `.env.*` are gitignored (`.gitignore:12-13`); `git ls-files | grep -E '(^|/)\.env$'` → **none**. No `.env` exists in history.
