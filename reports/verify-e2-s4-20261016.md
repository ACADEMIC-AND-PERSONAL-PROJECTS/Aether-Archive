Contracts the suite pins (44 tests in the tree, all in jsdom):

- `oklch`: transform round-trips, ΔE symmetry and separation;
- `downscale`: untouched within budget, long-edge cap with aspect, box average exactness, premultiplied
  alpha (transparent black does not darken), uniformity preserved;
- `quantize`: three-group recovery with exact counts (k-means++) and median-split arithmetic (median
  cut), determinism, empty clusters dropped, k > n, empty input;
- `score`: near-black/white dropped, merge into count-weighted mean, wide-threshold total collapse,
  ranking by share, mid-lightness bonus, chroma boost;
- `palette`: dominant hue first with weight ≈ 0.7, low-saturation stays low-saturation, grayscale
  recovered exactly with no chroma, transparent half ignored at full weight, determinism over seeded
  noise, 5–8 contract, the ΔE invariant, near-black/white regions dropped, dominant mass ≥ 0.40 on the
  jittered photo;
- `decode`: aspect-preserving pre-size (200×100 → 64×32), never upscales, `decode-failed` funnel,
  `unsupported` for a missing context, `unsupported` where the globals are absent (the jsdom finding,
  pinned), bytes → palette end-to-end with injected dependencies.

## 4. The algorithm decision, measured

Protocol: a probe test (temporary, deleted after the run) over the **shipped modules** — synthetic
jittered photo (45% rust `#bc5634` / 30% deep teal / 15% sand / 10% near-black, ±12 per channel);
warm-up, then mean of runs on Node 22.23.3:

| Measure | k-means++ | median cut |
| --- | --- | --- |
| clustering 4,096 px, k = 8 | 7.58 ms | 6.57 ms |
| full pipeline, 64×64 | **8.19 ms** | 10.50 ms |
| full pipeline, 512² → 64 px | **10.71 ms** | 15.55 ms |
| colours returned | 8 | 7 |
| top-1 ΔE to the dominant centre | 0.24 | **0.0031** |
| weighted coverage (ΔE) | 0.0105 | **0.0079** |

`weighted coverage` is Σ region share × ΔE(region centre, nearest returned colour) — in this probe
0.45·d(rust) + 0.30·d(teal) + 0.15·d(sand) + 0.10·d(dark); lower means the palette describes the
photo's masses more faithfully.

Full JSON:

```json

    "method": "mean of runs after one warm-up"
  },
  "kmeans": {
    "clustering4096pxK8Ms": 7.58,
    "pipeline64Ms": 8.19,
    "pipeline512Ms": 10.71,
    "colors": 8,
    "hexes": ["#1d6068", "#bc5035", "#c35a34", "#b65b34", "#debe97", "#deca95", "#24241c", "#22191c"],

    "top1Hex": "#bd5735",

    "weightedCoverage": 0.0079
```

**Reading.** Everything is inside §2.1's 50 ms budget; k-means++ is ahead on the pipeline. On this
protocol median cut wins top-1 and coverage because it folds the heterogeneous rust region into a
single centroid — the same behaviour that makes it emit `#cf855c`, a blend absent from the photo,
between rust and sand. k-means++ instead splits rust into three real tones: 0.19 + 0.135 + 0.125 =
**0.45**, its true mass (pinned in the suite), and every returned hex exists in its source region. For
theming, that description is more useful than a computed blend — so **k-means++ ships as the default**;
median cut ships selectable and tested by the same suite. Decision recorded: ADR-018.

## 5. Browser probe — the real decode path in Chromium

The decode stage was probed in real Chromium (152.0.7977.82, Fedora 44) against the **built** module,
offline: a temporary probe page rendered PNGs on a canvas → `toBlob` → `decodeToPixels` →
`extractPalette`. `--dump-dom` fires at the `load` event, so the page also requests a deliberately slow
image (8 s) — the probe finishes long before `load`, and the dump carries the finished JSON.
(`--virtual-time-budget` and `--timeout` are ignored by current headless mode; observed, hence the
slow resource.)

Commands (from `frontend/`):

```bash
npx vite build --config vite.probe.config.ts          # temp config: probe page → dist-probe
python3 /tmp/opencode/serve_probe.py dist-probe &     # temp server: static files + /slow.png (8 s)
chromium-browser --headless=new --no-sandbox --disable-gpu --disable-dev-shm-usage \
  --dump-dom http://127.0.0.1:4199/probe/e2s4-probe.html > /tmp/opencode/e2s4-probe-raw3.html
grep -o 'E2S4_PROBE.\{0,4000\}' /tmp/opencode/e2s4-probe-raw3.html
```

## 8. Deviations & recorded scope

- **Roles and contrast are not here** — §2.1's role derivation and §2.2's contrast guarantees belong
  to `theme.ts` in E2-S6; recorded on issue #23 before implementation. E2-S4 ships the scored palette.
- **Median cut ships as an alternative** rather than being dropped — both implementations are measured
  (ADR-018); the switch back is one line if later stories prefer top-1 dominance.
- **No `vitest bench`** — not exported by vitest 5.0.5 (probed); measurements come from a probe test.
- **No new dependencies** — `package.json` and lock untouched; no browser-mode runner.
