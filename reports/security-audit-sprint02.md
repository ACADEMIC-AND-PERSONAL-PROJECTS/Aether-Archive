### Informational notes (no action required for this release)

- **N1 — hand-dropped files are served from the platform media-type table.** `ImageServingConfig.java:42-54` documents it: the six extensions the upload path can write (`jpg jpeg png gif webp avif`) have media types of the archive's own, but a name no upload can produce — one dropped into `images/` by hand — is answered from the platform's table (`.html` → `text/html`, `.xyz` → `chemical/x-xyz`), with `X-Content-Type-Options: nosniff` pinned on every answer. `nosniff` stops sniffing, not the rendering of a correctly-typed document, so a hand-placed `.html` is a browsable same-origin page; only the operator can place it, and the behaviour is a deliberate design choice argued in the Javadoc ("neither a second whitelist … nor a silent `application/octet-stream`"). Recorded, not flagged.
- **N2 — dev database password fallback, pre-existing.** `backend/src/main/resources/application.yml:28` — `password: ${POSTGRES_PASSWORD:change-me-local}`. Unchanged this sprint (file not in the diff), overridden by `.env` (gitignored; only `.env.example` was ever committed — verified against full history). Not a secret; carry-over from the Sprint 1 audit.
- **N3 — `VITE_API_BASE_URL` is a build-time escape hatch.** Documented in `frontend/src/vite-env.d.ts:14-24` and `.env.example`: a bundle built with it set embeds an absolute plain-HTTP API origin, bypassing the dev proxy. Works as documented; release builds should simply be made without it (or with the intended origin). Informational.
- **N4 — no Content-Security-Policy on the app shell.** `frontend/index.html` ships no CSP meta and nothing in this repo sets response headers for the app (the deployment story, E6, owns that layer; no deployment config changed this sprint). With React escaping intact (sweeps below) and a zero-external-request bundle, CSP is hardening rather than an open hole; note it for the deployment story together with `frame-ancestors`/clickjacking.
