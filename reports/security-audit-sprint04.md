## OWASP-oriented review

**CI/CD Security + GitHub Actions Security cheat sheets** (the sprint's new sensitive surface — URLs above) — verified point by point:

- **Dangerous triggers**: none. `pull_request` (branches `develop`, `main`) and `push` on `develop` only (`ci.yml:15-19`) — no `pull_request_target`, no `workflow_run`, no `issue_comment`. The fork-safety argument is the `pull_request` one: fork PRs get a read-only `GITHUB_TOKEN` and no secrets (GitHub docs, above).
- **Action pinning**: every one of the four `uses:` is a full 40-hex commit SHA with a `# v4` comment (`ci.yml:37, 42, 55, 72, 77`). The cheat sheet's "check for impostor commits" step was performed by hand: each SHA resolves to a real commit **inside the official `actions/*` repository** (evidence in Checks §8). `actions/checkout` uses `persist-credentials: false` in both jobs (`:39, :74`) — the sheet calls this out by name.
- **Least privilege**: `permissions: contents: read` at workflow level (`:21-22`); repo default token is `read` with `can_approve_pull_request_reviews: false` (live settings); no secret, credential or `secrets.` reference anywhere in the file; no `${{ }}` interpolation inside any `run:` block (script-injection guidance — checked, zero hits).
- **Enforcement**: branch protection on **both** `develop` and `main` requires exactly the two job names (`app_id 15368`), with `enforce_admins: true`, no force-push, no deletion; the run at the audit point shows both checks `completed/success`. A rename of a job breaks the gate loudly (the workflow carries its own warning at `:30-31, :65-66`).
- **Gaps recorded, not hidden**: fork approval is `first_time_contributors` (sheet recommends `all_external_contributors`); `sha_pinning_required: false` and `allowed_actions: all` leave the pinning convention file-level rather than policy-level; no Dependabot for Actions yet (planned as **E6-S22**, which the workflow comment itself references); commits are not required to be signed; Maven/npm caching is enabled in a test-and-build workflow (the sheet's cache-poisoning warning targets release/publishing workflows — none exists here; residual noted). All of this is N7's territory and none of it is exploitable as configured (no secrets, read-only token, single-owner merge).

**XSS Prevention Cheat Sheet** (URL above) — the new colour/theme surface:

- Sweep of `frontend/src` for `dangerouslySetInnerHTML|innerHTML|eval\(|new Function|document\.write|srcDoc` → **zero hits** (fresh run).
- The aura path cannot inject CSS: `normalizeHex` accepts only `#` + six hex digits (`contrast.ts:17,34-36`); extraction emits canonical hex (`rgbToHex`/`oklabToHex`, `oklch.ts:63,71`); `themeFromBackground` re-validates and refuses pure black/white (`theme.ts:296-303`); `applyTheme` writes **nine fixed property names** (`THEME_PROPERTIES`, `theme.ts:43-53`) with those validated values through `style.setProperty` (`theme.ts:449-452`).
