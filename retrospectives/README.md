# Retrospectives

One file per sprint: `sprintNN.md` (two-digit number), written by `/finish-sprint` **before** the
release PR so the retrospective ships with the release.

A retrospective is read by the project owner to follow the work without reading the whole git history.
It must therefore contain **real numbers and links**, never vague summaries:

- stories committed vs delivered, points, velocity (from `docs/scrum/SPRINT-PLAYBOOK.md`),
- PR links and commits of interest,
- what went well / what did not / what changes next (2–3 verifiable process changes),
- decisions taken (ADR links) and carry-over.

Start from `TEMPLATE.md`. Keep it under ~120 lines.
